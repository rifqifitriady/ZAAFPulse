# Tiru penerjemah 9router, tinggalkan jalur OAuth-nya

9router menghubungkan alat coding AI ke puluhan provider lewat satu proses Node.js/Next.js di port 20128. Proses itu melayani empat wire format sekaligus: OpenAI `/v1/chat/completions`, Anthropic `/v1/messages`, OpenAI `/v1/responses` dan Gemini `/v1beta/models/*`. Setiap request diterjemahkan lewat format tengah OpenAI Chat Completions ke format upstream yang dibutuhkan. Registry-nya berisi **138 file provider**, sekitar **95 di antaranya provider chat**, jadi klaim "40+ provider" malah konservatif. Klaim "100+ model" belum terverifikasi sebagai satu angka. Fitur "smart router"-nya nyata, tetapi lebih sederhana daripada pemasarannya. RTK adalah filter teks JavaScript sekitar 900 baris yang *memotong* output tool, jadi tidak lossless. Quota tracking dan auto token refresh terutama melayani token OAuth langganan (Claude Pro/Max, Copilot, Antigravity, Gemini CLI, Kiro). Ketentuan Anthropic secara eksplisit melarang token semacam itu dirutekan lewat proxy, dan 9router sendiri memberi label risiko ban pada keenam provider tersebut. ZAAFPulse paling diuntungkan bila memindahkan lapisan yang aman dan bebas dependensi: endpoint `/v1/messages` dan `/v1/responses` dengan state machine streaming, port RTK yang diperbaiki dan dicatat di usage log, cooldown per-akun, serta pembacaan header rate-limit resmi. Yang harus ditolak ada lima: semua alur OAuth langganan, penyamaran identitas klien, padding usage +2.000 token, MITM dengan root CA, dan tunnel relay pihak ketiga. Dengan dua endpoint baru, ZAAFPulse bisa melayani Claude Code, Codex, Copilot BYOK, OpenCode, Cline, Kilo, Continue, Aider, Zed, Qwen Code, Factory Droid dan OpenClaw dari 127.0.0.1. Cursor, Antigravity, Kiro dan Windsurf tidak bisa dijangkau secara sah dari localhost.

## Satu port melayani empat wire format, alat lain dijangkau lewat file konfigurasi atau MITM

Inti arsitektur 9router adalah folder `open-sse/` yang berdiri sendiri. Di dalamnya ada translator, executor per provider, logika combo, account fallback dan RTK. Folder ini dibungkus aplikasi Next.js 16 berbahasa JavaScript ESM yang menyimpan state di SQLite di bawah `~/.9router` ([CLAUDE.md](https://github.com/decolua/9router/blob/87a74e1/CLAUDE.md), [README.md](https://github.com/decolua/9router/blob/87a74e1/README.md)). Alur request berjalan dari route `src/app/api/v1/*` ke `src/sse/handlers/chat.js`, yang mengurai request, mengembangkan combo dan memutar akun. Dari sana request masuk ke `open-sse/handlers/chatCore.js`, yang mendeteksi format klien, menerjemahkan, mengirim, lalu mengulang atau me-refresh token bila perlu. Executor per provider ada di `open-sse/executors/*`; `default.js` menangani semua upstream yang kompatibel dengan OpenAI ([docs/ARCHITECTURE.md](https://github.com/decolua/9router/blob/87a74e1/docs/ARCHITECTURE.md)). Ketiga endpoint chat (`/v1/chat/completions`, `/v1/messages`, `/v1/responses`) memanggil handler yang sama, `handleChat` → `handleChatCore`. Rewrite di [next.config.mjs](https://github.com/decolua/9router/blob/87a74e1/next.config.mjs) menambahkan alias `/v1/v1/*`, `/responses`, `/codex/*` dan `/v1beta/*` agar klien yang salah menyusun URL tetap sampai di handler yang benar. Inilah mekanisme "satu gateway untuk semua alat". Tiap alat bicara dalam format aslinya, dan gateway yang menanggung beban penerjemahan.

Alat coding dihubungkan dengan dua cara berbeda. Untuk sekitar 20 alat, dashboard menggabungkan blok provider ke file konfigurasi milik alat itu sendiri ([src/shared/constants/cliTools.js](https://github.com/decolua/9router/blob/87a74e1/src/shared/constants/cliTools.js)). Claude Code mendapat `ANTHROPIC_BASE_URL=http://127.0.0.1:20128/v1` dan `ANTHROPIC_AUTH_TOKEN` di blok `env` `~/.claude/settings.json`, ditambah variabel `ANTHROPIC_DEFAULT_*_MODEL` ([claude-settings/route.js](https://github.com/decolua/9router/blob/87a74e1/src/app/api/cli-tools/claude-settings/route.js)). Codex mendapat tabel `[model_providers.9router]` dengan `wire_api = "responses"` di `~/.codex/config.toml` ([codex-settings/route.js](https://github.com/decolua/9router/blob/87a74e1/src/app/api/cli-tools/codex-settings/route.js)). OpenCode, Cline, OpenClaw, Kilo, Factory Droid dan lainnya mendapat entri JSON, YAML atau TOML yang setara. Jalur dashboard tidak membuat backup dan tidak membatasi izin file. Cline bahkan mendapat `openAiApiKey` dalam plaintext di `~/.cline/data/secrets.json` ([cline-settings/route.js](https://github.com/decolua/9router/blob/87a74e1/src/app/api/cli-tools/cline-settings/route.js)). Hanya jalur CLI `npx 9router connect` yang membuat backup `.bak-9router` dan menulis dengan mode 0600 ([connect.js](https://github.com/decolua/9router/blob/87a74e1/cli/src/cli/commands/connect.js)). README-nya juga basi: README masih menyuruh mengedit `~/.claude/config.json` dengan `anthropic_api_base`, padahal kode dan dokumentasi resmi memakai `ANTHROPIC_BASE_URL` ([Claude Code connect](https://code.claude.com/docs/en/llm-gateway-connect)).

Cara kedua dipakai untuk alat yang tidak menyediakan custom endpoint, yaitu Antigravity, Kiro dan Copilot versi lama. Untuk alat-alat ini 9router memakai MITM. Ia menambahkan host seperti `daily-cloudcode-pa.googleapis.com` dan `runtime.us-east-1.kiro.dev` ke `/etc/hosts` lewat `sudo`. Ia juga membuat "9Router MITM Root CA" berumur 10 tahun, memasangnya sebagai trusted root di System Keychain, dan menjalankan proxy sebagai root di port 443 setelah mematikan proses apa pun yang sedang memakai port itu ([src/mitm](https://github.com/decolua/9router/tree/87a74e1/src/mitm), [dnsConfig.js](https://github.com/decolua/9router/blob/87a74e1/src/mitm/dns/dnsConfig.js)). Password sudo disimpan terenkripsi dengan kunci yang diturunkan dari machine id ([manager.js](https://github.com/decolua/9router/blob/87a74e1/src/mitm/manager.js)). Cursor hanya mendapat panduan dan butuh URL publik, karena "Cursor routes requests through its own server, so local endpoint is not supported" ([cliTools.js](https://github.com/decolua/9router/blob/87a74e1/src/shared/constants/cliTools.js)). Untuk keperluan itu 9router mengunduh `cloudflared` dari `releases/latest` tanpa checksum, lalu mendaftarkan URL-nya ke relay pihak ketiga `abc-tunnel.us` ([src/lib/tunnel/cloudflare](https://github.com/decolua/9router/tree/87a74e1/src/lib/tunnel/cloudflare)).

Peta alat di bawah menunjukkan format yang harus dilayani ZAAFPulse (http://127.0.0.1:4777) agar tiap alat bisa tersambung, berdasarkan dokumentasi resmi masing-masing alat.

| Alat | Wire format yang dibutuhkan | Header auth | Bisa dari 127.0.0.1? |
|---|---|---|---|
| Claude Code | Anthropic Messages `/v1/messages` (SSE) | `Authorization: Bearer` atau `x-api-key` | Ya |
| Codex CLI | OpenAI Responses `POST /v1/responses` saja | `Authorization: Bearer` | Ya |
| Gemini CLI | Gemini `/v1beta/models/{m}:streamGenerateContent?alt=sse` | `x-goog-api-key` | Ya (HTTP diizinkan untuk localhost) |
| Copilot VS Code (Custom Endpoint) | Chat Completions, Responses atau Messages via `apiType` | Disimpulkan dari `apiType` | Kemungkinan besar; belum dikonfirmasi |
| OpenCode, Cline, Roo, Kilo, Continue, Aider, Zed, Qwen Code, Droid, OpenClaw | Chat Completions; sebagian juga Messages atau Responses | Bearer / `x-api-key` | Ya |
| Cursor | Chat Completions (Ask) dan Responses (Agent), dikirim **dari cloud Cursor** | Bearer | Tidak |
| Antigravity, Kiro, Windsurf, Amp | Tidak ada jalur first-party yang terdokumentasi | – | Tidak |

Sumber matriks: [Claude Code gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol), [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference), [gemini-cli configuration.md](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/configuration.md), [VS Code language models](https://code.visualstudio.com/docs/copilot/customization/language-models), [Cursor API keys](https://cursor.com/docs/settings/api-keys) dan [Kiro issue #9367](https://github.com/kirodotdev/Kiro/issues/9367). Ada dua batasan penting. Codex tidak bisa lagi memakai Chat Completions, karena "`responses` is the only supported value" untuk `wire_api` ([Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)). Bukti tentang Antigravity, Windsurf dan Amp hanya berasal dari sumber pihak ketiga yang saling bertentangan. Konsekuensinya bagi ZAAFPulse jelas: endpoint `/v1/chat/completions` yang ada sekarang hanya menjangkau separuh lanskap alat, sedangkan Claude Code dan Codex, dua alat terpenting, tidak terjangkau.

## Penerjemahan berporos pada OpenAI Chat dan empat state machine streaming

Mesin penerjemahnya sederhana secara konsep. `translateRequest(source, target)` mencari translator langsung `source:target` lebih dulu. Bila tidak ada, ia menempuh `source → openai → target`, dan `translateResponse` melakukan hal yang sama per chunk ([open-sse/translator/index.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/index.js)). Format klien dideteksi dari URL lebih dulu (`/v1/messages` → claude, `/v1/responses` → openai-responses). Bila belum jelas, deteksi berlanjut ke isi body: `input` tanpa `messages` berarti Responses, `contents[]` berarti Gemini, dan `system` atau `tool_use`/`tool_result` berarti Claude ([formats.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/formats.js), [provider.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/services/provider.js)). Ketika klien memanggil upstream aslinya, misalnya Claude Code ke Anthropic, penerjemahan dilewati sepenuhnya dan hanya model serta kredensial yang ditukar ([clientDetector.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/utils/clientDetector.js)). Passthrough ini penting untuk ZAAFPulse. Rute Claude Code → Anthropic API key tidak perlu diterjemahkan sama sekali, jadi `cache_control`, blok thinking dan signature tetap utuh.

Pemetaan request mengikuti pola yang bisa diprediksi. Dari OpenAI ke Claude, role `tool` menjadi `user`, giliran ber-role sama digabung, `tool_choice: "required"` menjadi `{type: any}`, dan `response_format` menjadi teks system tambahan ([openai-to-claude.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/request/openai-to-claude.js)). Dari Responses ke Chat, `instructions` menjadi pesan system, `function_call` menjadi `tool_calls`, dan `function_call_output` menjadi `{role: "tool", tool_call_id}`. Custom tool diubah menjadi function dengan satu parameter string `input` ([openai-responses.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/request/openai-responses.js)). Dari OpenAI ke Gemini, `system` menjadi `systemInstruction`, `assistant` menjadi `model`, dan `max_tokens` menjadi `generationConfig.maxOutputTokens` ([openai-to-gemini.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/request/openai-to-gemini.js)). Intent thinking dibaca dari `reasoning_effort`, `reasoning.effort`, `thinking.budget_tokens` atau `output_config.effort`, lalu ditulis ulang dalam bentuk target memakai tabel `LEVEL_TO_BUDGET`: low 1024, medium 8192, high 24576, max 128000 ([thinkingUnified.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/concerns/thinkingUnified.js)). Bagian yang paling layak ditiru adalah sanitasi tool call. ID dibersihkan ke pola `^[a-zA-Z0-9_-]+$`, tool result yang hilang diisi kosong, dan ID duplikat untuk Gemini diganti nama menjadi `id-2`, `id-3` ([toolCall.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/concerns/toolCall.js)). Pengunduhan gambar untuk upstream Gemini juga dilindungi dari SSRF: IP privat dan metadata diblokir, redirect ditolak, dan unduhan dibatasi 10 MB dan 10 detik ([prefetch.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/concerns/prefetch.js)).

Streaming ditangani empat state machine kecil di [open-sse/utils/stream.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/utils/stream.js) dan folder `translator/response/`. Arah Claude → OpenAI memetakan `text_delta` ke `content`, `thinking_delta` ke `reasoning_content` dan `input_json_delta` ke `tool_calls[].function.arguments`. Arah OpenAI → Claude mengeluarkan `message_start`, membuka dan menutup blok `content_block_*`, lalu ditutup `message_delta` dan `message_stop` ([openai-to-claude.js response](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/response/openai-to-claude.js)). Arah OpenAI → Responses mengeluarkan urutan lengkap `response.created` → `output_item.added` → `output_text.delta` → `response.completed`. Tabel finish reason (`end_turn`↔`stop`, `max_tokens`↔`length`, `tool_use`↔`tool_calls`) dan tabel usage (`prompt_tokens` = `input_tokens` + cache read + cache creation) ada di [finishReason.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/concerns/finishReason.js) dan [usage.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/concerns/usage.js). Semua ini murni pemetaan objek dan parsing SSE baris demi baris. Seluruhnya bisa ditulis ulang dengan `node:http` dan `fetch` tanpa satu pun paket npm.

Implementasi 9router punya celah yang harus diperbaiki ZAAFPulse. Translator OpenAI → Claude **tidak mengirim event `ping`**. Padahal dokumentasi Claude Code menyatakan bahwa gateway yang menerjemahkan dari upstream tanpa ping harus "emit its own `ping` events", karena kalau tidak, idle timeout akan terpicu saat model berpikir lama. Claude Code juga akan "stalls" bila respons di-buffer, dan menganggap stream yang berakhir sebelum `message_stop` sebagai koneksi putus ([Claude Code gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol)). Error body harus diteruskan tanpa diubah, karena logika retry Claude Code mencocokkan kata-kata error. Bila upstream menolak `thinking` atau `cache_control`, Claude Code akan mencoba ulang dan mematikan kapabilitas itu, tetapi hanya jika pesan error-nya utuh. Untuk Codex, kebutuhan minimumnya lebih ringan dari dugaan. Parser Codex secara eksplisit mengabaikan `function_call_arguments.delta`, `content_part.*` dan `output_text.done`, dan mengambil tool call dari `response.output_item.done` ([codex sse/responses.rs](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/sse/responses.rs)). Jadi ZAAFPulse cukup mengirim `response.created`, `output_item.added`, `output_text.delta`, `output_item.done` dan `response.completed` yang membawa usage. Field `sequence_number` dan `output_index` tetap layak ditambahkan untuk klien Responses lain seperti Copilot, Droid dan Zed.

Ada empat perilaku 9router yang **tidak boleh disalin**. Pertama, setiap request OpenAI → Claude diberi blok system pertama `"You are Claude Code, Anthropic's official CLI for Claude."` ([appConstants.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/config/appConstants.js) L184). Kedua, `applyCloaking` untuk token OAuth Claude memalsukan `x-anthropic-billing-header` dan `metadata.user_id` ([claudeCloaking.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/utils/claudeCloaking.js)). Ketiga, thinking signature default di-hard-code ([defaultThinkingSignature.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/config/defaultThinkingSignature.js)). Keempat, `addBufferToUsage` menambahkan **`BUFFER_TOKENS = 2000`** ke `prompt_tokens` yang dilihat klien "to prevent context errors" ([usageTracking.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/utils/usageTracking.js)). Dua yang pertama adalah penyamaran identitas klien. Yang keempat akan merusak akurasi usage log dan perhitungan biaya ZAAFPulse. Translator Gemini juga menyetel kelima kategori `safetySettings` ke `"OFF"` ([formats/gemini.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/translator/formats/gemini.js)). ZAAFPulse sebaiknya membiarkan default provider. Route `/v1beta` milik 9router sendiri hanya menyimpan teks dan membuang tools serta gambar ([v1beta route](https://github.com/decolua/9router/blob/87a74e1/src/app/api/v1beta/models/%5B...path%5D/route.js)), jadi dukungan Gemini CLI di 9router lebih lemah dari kesan yang diberikan.

Saat menerjemahkan request Claude Code ke upstream non-Claude, ZAAFPulse harus menghapus field yang dikirim Claude Code ke nama model apa pun yang tidak dikenalnya. Field itu adalah `thinking: {type: "adaptive"}`, `cache_control`, `context_management`, `output_config`, serta `strict` dan `defer_loading` pada tool. Field-field ini memicu `400 Extra inputs are not permitted` di upstream non-Anthropic ([Claude Code gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol)). Snippet setup ZAAFPulse juga sebaiknya menyertakan `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` dan `CLAUDE_CODE_ATTRIBUTION_HEADER=0` untuk memperkecil permukaan masalah. Satu catatan sikap resmi perlu diingat: Anthropic "doesn't support routing Claude Code to non-Claude models through any gateway" ([Other LLM gateways](https://code.claude.com/docs/en/llm-gateway)). Rute seperti itu boleh dibangun, tetapi ZAAFPulse harus memperlakukannya sebagai mode tanpa dukungan vendor dan menandainya demikian di UI.

## RTK memotong output tool, bukan mengompresinya tanpa kehilangan

"RTK Token Saver" adalah port JavaScript yang ditulis ulang dari filter CLI Rust "rtk" (Rust Token Killer). File konstantanya dibuka dengan "RTK port constants (mirror Rust defaults)" dan merujuk baris sumber Rust seperti `git.rs L325-413` ([constants.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/rtk/constants.js)). Tidak ada program luar yang dijalankan. Fungsi `compressMessages` menyunting body di tempat dan menyasar empat bentuk tool result: OpenAI Chat `role: "tool"`, Responses `function_call_output.output`, Anthropic `tool_result` dan Kiro `toolResults`. **Gemini `functionResponse` dilewati sama sekali** ([rtk/index.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/rtk/index.js)). Hasil di bawah **500 karakter** atau di atas **10 MiB** tidak disentuh, begitu pula hasil yang ditandai `is_error`. Bila filter melempar error, atau output-nya kosong atau tidak lebih pendek, teks asli dipertahankan ([applyFilter.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/rtk/applyFilter.js)). Sifat fail-open ini benar dan wajib dipertahankan.

Pemilihan filter hanya berdasarkan **1024 karakter pertama** output, bukan nama tool atau perintahnya. Urutan deteksinya git log, git diff, git status, output build (npm, cargo, maven, pip), grep, find, tree, ls, file read bernomor, lalu fallback dedup-log dan smart-truncate ([autodetect.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/rtk/autodetect.js)). Aturannya pemotongan dengan batas tetap. Diff dibatasi 100 baris per hunk dan 500 baris total. Git status dibatasi 10 file per kategori. Grep dibatasi 10 hasil per file. Output build menyimpan semua error tetapi hanya 5 warning pertama. File read dan smart-truncate menyimpan **120 baris awal dan 60 baris akhir** dengan penanda `... +N lines truncated` di tengahnya ([rtk/filters](https://github.com/decolua/9router/tree/87a74e1/open-sse/rtk/filters)). Jadi kata "lossless" di README tidak akurat. Model tidak pernah melihat baris yang dibuang. Filter git diff bahkan menambahkan footer `[full diff: rtk git diff --no-compact]` yang menyesatkan, karena perintah itu tidak ada di mesin pengguna. Angka penghematan "20-40%" di README dan "60-90%" di dashboard tidak diukur oleh kode. Penghematan dihitung dalam karakter, hanya jalur Cursor yang mencatat persentasenya, dan tidak ada yang disimpan ke storage usage ([chatCore.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/handlers/chatCore.js)). Sepuluh kasus `rtk.test.js` juga tercatat sebagai kegagalan yang diketahui ([tests/__baseline__](https://github.com/decolua/9router/tree/87a74e1/tests/__baseline__)).

Fitur ini tetap layak diadopsi karena masalah yang diselesaikannya nyata. Agen coding menghabiskan sebagian besar konteks pada output `git diff`, log build dan hasil grep yang panjang, dan kodenya kecil serta bebas dependensi. ZAAFPulse sebaiknya menjalankannya pada format klien *sebelum* penerjemahan, bukan setelahnya seperti yang dilakukan 9router untuk semua provider kecuali Cursor. Dengan begitu filter cukup memahami bentuk OpenAI, Anthropic dan Responses, tidak peduli upstream-nya. Ada beberapa perbaikan yang membuat versi ZAAFPulse lebih baik dari aslinya. Filter dipilih dari nama dan argumen tool call yang memicu hasil itu (misalnya `Bash` dengan `git diff`), bukan ditebak dari teks. Kode ANSI dibuang. Penghematan dihitung dalam token dan ditulis ke usage log di samping token input dan biaya, agar klaim penghematan bisa diaudit. Footer `rtk` yang menyesatkan dihapus. Header per-request untuk mematikan fitur, seperti `x-9router-token-saver: off` di 9router ([runtimeConfig.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/config/runtimeConfig.js) L68), dipertahankan. Dua catatan kehati-hatian juga perlu dicatat. Pemotongan bisa membuang baris yang justru dibutuhkan model, jadi fitur ini sebaiknya dimulai per-route dan bukan global. Lisensi rtk-ai/rtk belum diperiksa, dan folder `open-sse/rtk/` tidak memuat salinan lisensinya, jadi lisensi upstream harus dicek sebelum menyalin logika filter baris demi baris. Saudara-saudara RTK tidak perlu diadopsi. Caveman dan Ponytail hanya menyuntik system prompt. Headroom memanggil layanan Python eksternal. PXPIPE memasang `pxpipe-proxy@latest` tanpa pin versi ([pxpipe.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/rtk/pxpipe.js)), yang bertentangan langsung dengan prinsip zero-dependency.

## Routing, quota dan refresh token: polanya bagus, sumber datanya bermasalah

Routing 9router terdiri dari dua loop bersarang. Combo adalah daftar bernama string `provider/model`. Combo dijalankan dengan strategi `fallback` (berurutan), `round-robin` (diputar dengan sticky count), atau `fusion`, di mana beberapa model menjawab paralel dan model juri menulis jawaban akhir ([combo.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/services/combo.js)). Di dalam tiap model, loop akun memilih koneksi dengan `fill-first` berdasarkan prioritas, atau `round-robin` yang tetap memakai akun terakhir sampai 3 kali berturut-turut ([auth.js](https://github.com/decolua/9router/blob/87a74e1/src/sse/services/auth.js)). "Tiering" Subscription → Cheap → Free tidak punya logika khusus. Tiering itu hanya urutan model dalam combo. Pola yang layak diambil ada empat. Pertama, klasifikasi error: teks "rate limit"/"quota exceeded" dan status 429 memicu backoff eksponensial `min(2000·2^(level−1), 5 menit)`, status 401–404 memicu cooldown 2 menit, dan 4xx lain tidak memicu fallback ([errorConfig.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/config/errorConfig.js), [accountFallback.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/services/accountFallback.js)). Kedua, deteksi respons 2xx tanpa konten sebagai kegagalan. Ketiga, pengurutan ulang model berdasarkan kapabilitas ketika giliran user berisi gambar atau PDF. Keempat, sticky round-robin yang menjaga cache hit prompt. Route `router/<name>` milik ZAAFPulse sudah setara dengan lapisan combo, jadi keempat pola ini bisa ditambahkan langsung di atasnya.

Quota tracking adalah bagian yang paling bergantung pada akses tidak resmi. Setiap handler di `open-sse/services/usage/` memanggil endpoint internal layanan langganan. Claude memakai `GET https://api.anthropic.com/api/oauth/usage` dengan UA `claude-cli` yang dipalsukan ([usage/claude.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/services/usage/claude.js)). Codex memakai `chatgpt.com/backend-api/wham/usage` ([usage/codex.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/services/usage/codex.js)). Copilot memakai `api.github.com/copilot_internal/user` ([usage/github.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/services/usage/github.js)). Google memakai `v1internal:retrieveUserQuota` ([usage/google.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/services/usage/google.js)). Hasilnya dinormalisasi menjadi `{used, total, remaining, remainingPercentage, resetAt}` dan ditampilkan sebagai bar hijau, kuning dan merah dengan hitung mundur reset. Fitur opt-in "quota auto-ping" bahkan mengirim request kecil tepat setelah reset untuk "menghangatkan" jendela 5 jam Claude dan Codex ([quotaAutoPing.js](https://github.com/decolua/9router/blob/87a74e1/src/shared/services/quotaAutoPing.js)). Ironisnya, header rate-limit resmi yang ada di setiap respons (`anthropic-ratelimit-*`, `retry-after`) hanya diteruskan ke klien dan tidak pernah di-parse ([upstreamHeaders.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/utils/upstreamHeaders.js)). Untuk ZAAFPulse yang hanya memakai API key, sumber quota yang andal justru header itu: Anthropic `anthropic-ratelimit-requests-remaining`/`-tokens-reset` dan OpenAI `x-ratelimit-remaining-requests`/`-tokens`. Membaca header tersebut di jalur streaming memberi sisa quota secara langsung tanpa request tambahan. Nilai `resetAt` hasil parsing juga bisa langsung mengisi cooldown akun, meniru cara 9router menghormati `resets_at` dari provider.

Auto token refresh berjalan di tiga titik. Refresh pertama terjadi sebelum setiap request, bila token akan kedaluwarsa dalam lead time per provider (default 5 menit, Claude 4 jam). Refresh kedua bersifat reaktif setelah 401 atau 403, dengan sampai 3 percobaan lalu satu kali replay. Refresh ketiga dijalankan scheduler latar belakang setiap 5 menit untuk token yang kedaluwarsa dalam max(lead, 30 menit) ([oauthCredentialManager.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/services/oauthCredentialManager.js), [backgroundTokenRefresh.js](https://github.com/decolua/9router/blob/87a74e1/src/sse/services/backgroundTokenRefresh.js)). Dua kunci mencegah refresh ganda: `dedupRefresh` berkunci `provider:oldToken` dan `withCredentialRefreshLock` berkunci `provider:connectionId`. Token terbaru juga dibaca ulang tepat sebelum refresh, sehingga refresh token yang berotasi (OpenAI, xAI) tidak pernah dipakai dua kali. Desain ini solid dan mudah diport memakai `fetch`, `crypto` dan `setInterval().unref()`. Masalahnya ada pada objek yang di-refresh. Client id yang dipakai adalah milik aplikasi resmi: Claude Code `9d1c250a-…`, Copilot VS Code `Iv1.b507a08c87ecfe98`, serta client Gemini CLI dan Antigravity lengkap dengan secret-nya ([tokenRefresh/providers.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/services/tokenRefresh/providers.js), [shared.js](https://github.com/decolua/9router/blob/87a74e1/open-sse/providers/shared.js)). Semua token disimpan **plaintext** di kolom JSON SQLite tanpa enkripsi ([connectionsRepo.js](https://github.com/decolua/9router/blob/87a74e1/src/lib/db/repos/connectionsRepo.js)). ZAAFPulse hanya perlu pola ini untuk kredensial yang memang sah di-refresh oleh pihak ketiga. Contoh utamanya JWT service account Vertex, yang di 9router di-mint ulang saat sisa waktunya kurang dari 5 menit. Token hasil refresh tetap disimpan di Keychain, bukan di file.

## Syarat layanan menarik garis tegas: API key ya, token langganan tidak

Posisi Anthropic paling eksplisit di antara semua provider. OAuth "is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications". Dokumen yang sama melanjutkan: "Anthropic does not permit third-party developers … to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens". Anthropic juga menyatakan berhak menegakkan aturan ini "without prior notice" ([Claude Code docs: Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). 9router melakukan semua yang dilarang itu. Ia menyimpan token OAuth Claude, menyamar sebagai Claude Code lewat system prompt, billing header, `metadata.user_id` sintetis dan header CLI, lalu menghangatkan jendela quota secara otomatis. Untuk Google, laporan sekunder dan forum menyebut gelombang restriksi 403 "ToS violation" pada akun Google AI Pro/Ultra yang memakai OAuth Antigravity lewat OpenClaw ([Trending Topics](https://www.trendingtopics.eu/google-blocks-paying-ai-subscribers-using-third-party-openclaw-tool/), [Google AI developer forum](https://discuss.ai.google.dev/t/account-restricted-without-warning-google-ai-ultra-oauth-via-openclaw/122778?page=3)). Untuk GitHub, balasan GitHub Support yang dikutip pengguna menyebut pemakaian Copilot lewat ekstensi tidak resmi "violates our Terms of Service" ([linux.do](https://linux.do/t/42333?tl=en)). OpenAI adalah pengecualian yang belum pasti. Sumber sekunder menyebut "Sign in with ChatGPT" didukung untuk alat developer pihak ketiga ([The New Stack](https://thenewstack.io/sign-in-with-chatgpt/)), tetapi teks ketentuan OpenAI sendiri tentang proxy self-hosted belum ditemukan. 9router sendiri menandai keenam provider langganan sebagai `deprecated` dengan peringatan: "not officially licensed for proxy/router use. Account may be restricted or banned" ([providersDisplay.js](https://github.com/decolua/9router/blob/87a74e1/src/shared/constants/providersDisplay.js)).

Garis aman bagi ZAAFPulse adalah **API key resmi saja**. Itu mencakup Anthropic API, OpenAI API, Gemini AI Studio key, Vertex service account, dan provider berbasis API key lain di registry 9router seperti DeepSeek, Groq, Mistral, OpenRouter dan GLM/Kimi/MiniMax lewat endpoint API key mereka. Semua alur OAuth langganan ditolak, begitu pula semua bentuk penyamaran klien. Penyamaran adalah bukti paling jelas adanya niat menghindari kontrol provider. Codex sign-in baru boleh dipertimbangkan setelah ketentuan OpenAI dibaca langsung. Postur keamanan juga perlu dibalik dari kebiasaan 9router. CLI 9router bind ke `0.0.0.0` secara default ([cli/cli.js](https://github.com/decolua/9router/blob/87a74e1/cli/cli.js) L110). Setiap request loopback melewati pemeriksaan API key ([dashboardGuard.js](https://github.com/decolua/9router/blob/87a74e1/src/dashboardGuard.js)). Password awalnya `123456` dan secret HMAC default untuk API key bersifat publik ([apiKey.js](https://github.com/decolua/9router/blob/87a74e1/src/shared/utils/apiKey.js)). Akibat bypass loopback, proses lokal apa pun bisa menghabiskan quota. ZAAFPulse harus bind hanya ke 127.0.0.1, mewajibkan API key bahkan dari loopback, dan membuat key dengan `crypto.randomBytes`. Penulis konfigurasi alat milik ZAAFPulse harus membuat backup, menulis dengan mode 0600, menghapus hanya key yang ia tambahkan saat reset, dan memakai referensi env var (`env_key` di Codex, `{env:VAR}` di OpenCode, `${VAR}` di Droid) alih-alih menulis secret ke file.

Tabel berikut menyusun keputusan adopsi menurut urutan nilai. Endpoint yang membuka alat terbanyak ada di atas, dan fitur yang melanggar ketentuan atau prinsip ZAAFPulse ada di bawah.

| Prioritas | Kemampuan | Keputusan | Cara aman dan zero-dependency |
|---|---|---|---|
| 1 | `POST /v1/messages` + SSE OpenAI → Anthropic | Adopsi, perbaiki | Passthrough untuk upstream Anthropic. Untuk upstream lain, state machine dengan `ping` setiap 10–15 detik, urutan event lengkap sampai `message_stop`, error body Anthropic-shaped tanpa diubah, dan hapus `thinking`/`cache_control`/`context_management`/`output_config` |
| 2 | `POST /v1/responses` + SSE (Codex, Copilot, Droid, Zed) | Adopsi | Event minimum ditambah `sequence_number`; `response.incomplete` untuk `max_output_tokens`; `response.failed` dengan `context_length_exceeded` |
| 3 | Auth multi-header, `count_tokens`, `/v1/models`, `HEAD /api/hello`, alias `/v1/v1/*` dan `/responses` | Adopsi | Terima `Authorization: Bearer`, `x-api-key`, `x-goog-api-key`; `count_tokens` sebagai estimasi chars/4; id alias yang memuat "claude" untuk discovery Claude Code, tanpa redirect |
| 4 | RTK token saver | Adopsi, perbaiki | Jalankan sebelum translasi; pilih filter dari nama tool; strip ANSI; catat token yang dihemat di usage log; fail-open; cek lisensi rtk |
| 5 | Cooldown per-akun, deteksi 2xx kosong, reorder kapabilitas, sticky round-robin | Adopsi | Tambahkan ke route `router/<name>` yang sudah ada |
| 6 | Quota tracking | Adopsi, ganti sumber | Parse header rate-limit resmi di jalur streaming, bukan endpoint internal langganan |
| 7 | Gemini `/v1beta/models/{m}:streamGenerateContent` | Adopsi belakangan | Lengkapi dengan tools dan gambar, yang dibuang oleh 9router; `safetySettings` tetap default provider |
| 8 | Penulis konfigurasi alat | Adopsi, perketat | Backup, mode 0600, referensi env var, reset yang hanya menghapus key milik ZAAFPulse |
| 9 | Auto token refresh | Terbatas | Hanya untuk kredensial sah (JWT Vertex); kunci per-koneksi; simpan di Keychain |
| – | OAuth Claude/Antigravity/Gemini CLI/Copilot/Kiro, cloaking, system prompt "You are Claude Code", padding usage, quota auto-ping | Tolak | Melanggar ketentuan Anthropic secara eksplisit dan berisiko ban di Google/GitHub |
| – | MITM root CA, tunnel `abc-tunnel.us`, unduhan `@latest` tanpa pin, Cursor | Tolak | Bertentangan dengan prinsip localhost-only dan zero-dependency |

## Kesimpulan

Pelajaran terpenting dari 9router adalah bahwa kompatibilitas alat kini ditentukan oleh **wire format**, bukan jumlah provider. Codex sudah menutup jalur Chat Completions, dan Claude Code hanya bicara Anthropic Messages. Akibatnya, gateway yang hanya menyediakan `/v1/chat/completions` tertinggal dari dua agen coding paling penting, berapa pun provider yang didukungnya. Sebaliknya, ZAAFPulse tidak perlu meniru 138 file registry. Provider API key yang kompatibel dengan OpenAI sudah cocok dengan model preset-nya, dan pekerjaan berat sesungguhnya adalah dua translator streaming yang benar. Kebenaran di sini menuntut standar yang lebih tinggi daripada yang dipenuhi 9router: ping keepalive, error body yang utuh, dan usage tanpa padding.

Implikasi kedua lebih strategis. Sebagian besar daya tarik 9router ("gratis", "pakai langganan Pro/Max di mana saja", quota bar untuk Copilot dan Claude) dibangun di atas akses yang oleh provider dilarang atau sedang diberantas. 9router sendiri sudah memberi label deprecated pada jalur itu dan mencatat beberapa free tier sebagai telah ditutup. Bagi ZAAFPulse, batasan API-key-only bukan kekurangan fitur. Batasan itu justru yang membuat usage log dan perhitungan biayanya bisa dipercaya, dan membuat alat ini tidak bisa mematikan akun pemiliknya sendiri. Ada empat ketidakpastian yang masih perlu dikonfirmasi sebelum implementasi: ketentuan OpenAI tentang Codex sign-in lewat proxy, apakah Copilot Custom Endpoint memanggil 127.0.0.1 dari extension host lokal, lisensi rtk-ai/rtk, dan skema resmi custom provider OpenClaw.
